# CareerLens 全栈优化与完善实施计划

版本：v1.0  
基准：2026-09-07 源码审计及现有验收记录  
性质：待实施计划；下文“新增、改造、验收目标”不表示已经实现  
目标用户：应届开发岗求职者，第一阶段优先支持个人本机使用

## 1. 总体目标与边界

将现有真实数据工作区，完善为“材料一致、匹配可信、操作可确认、结果可追溯”的求职产品。

完整主流程：

真实经历 → 结构化简历 → 不可变版本 → 确定的导出文件 → 岗位完整JD → 可解释匹配 → 建议审核与新版本 → 投递材料预览 → 单次确认 → 本地执行 → 回执核对 → 求职跟进

成功标准不是页面齐全，而是：
1. 编辑、预览、导出和投递引用同一版本的内容。
2. 每个评分和建议都能定位到当前发布版本的事实或明确的缺失项。
3. 点击按钮、HTTP成功和平台业务成功是不同状态。
4. 网络中断、页面变化、重复请求、服务重启不会被解释为已成功投递。
5. 用户能看到实际将发送的材料；批准只对确定的任务内容有效。
6. 无外部账号/密钥的环境可以验收本地业务和测试夹具，但不产生真实投递成功记录。
7. 个人本机版先稳定，再考虑多用户托管版。

本期不优先建设：更多招聘平台、无限批量投递、多轮自动代聊、微服务拆分、复杂推荐模型、完整招聘SaaS后台。验证码由用户完成，不设计验证码绕过或检测规避功能。

## 2. 已有基础与差距

| 模块 | 当前基础 | 主要差距 |
|---|---|---|
| 账号 | 注册、登录、退出、哈希令牌、按用户隔离 | 找回密码、请求限流、会话管理、Runner设备绑定 |
| 简历 | 草稿保存、发布、复制、恢复、差异接口 | 固定表单、动态多条经历、命名编辑、草稿/发布冲突 |
| 导入 | TXT/PDF/DOCX解析、原文保留 | 字段回填、原文定位、低置信度确认、JSON Resume转换 |
| 导出 | 浏览器打印 | 服务生成文件、稳定分页、模板/字体版本、文件哈希 |
| JD | 正文版本、提取、重要性修改 | 原子要求、真实确认状态/偏移/置信度、规则快照 |
| 匹配 | Java规则、别名、词项重叠、证据展示 | 否定句、复合要求、硬条件、证据白名单、统一评分引擎 |
| 建议 | 规则改写、缺失提示、审核应用 | 在线Provider调用链、事实验证、草稿冲突、稳定目标定位 |
| 发现 | Runner调用、岗位持久化、加入审核 | 分页/多城市、完整JD、搜索历史、变化追踪、批次关联 |
| 投递 | 审批、串行Runner、状态同步、核对入口 | 实际文件绑定、严格回执、未知结果、断电恢复、鉴权 |
| 跟进 | 投递记录与阶段修改 | 事件时间线、待办、终态、材料引用、提醒 |
| 工程化 | 构建、迁移、测试、Compose、CI | PostgreSQL实测、故障注入、备份恢复、质量评测 |

现有通过的测试作为回归基线保留，不能用测试数量替代功能覆盖范围。

## 3. 技术路线

### 3.1 保留现有技术栈

- Vue 3 + TypeScript：编辑、预览、审核、看板和运行状态。
- Spring Boot：鉴权、数据归属、版本、任务、审批和业务状态。
- PostgreSQL：生产业务事实来源、任务记录、Outbox和审计。
- H2：快速开发与部分测试；不替代PostgreSQL集成测试。
- FastAPI：解析、归一化、评分计算、建议生成与质量评测。
- 本地Runner：平台登录会话、页面操作、平台请求、本机检查点。
- 文件存储：先使用受控本地目录与元数据表，后续按需要接入对象存储。
- Redis：继续保持可选；没有明确瓶颈前，不为架构展示而强制引入消息队列。

### 3.2 明确三个事实来源

1. 简历事实：经过用户确认的内容及其发布版本。
2. 平台事实：原始岗位快照、平台响应和可核对的会话/提交结果。
3. 系统状态：数据库事务提交的任务、审批、事件和材料引用。

模型输出不是简历事实；执行器本地生成的追踪编号不是平台回执。

### 3.3 前端不承担任务调度

改造后，前端只创建任务、发送确认和观察状态。长任务由Core后台调度，浏览器关闭不影响已批准任务的进度记录。

## 5. M0：建立可执行的基线

### 任务

- 列出所有页面操作，对应接口、状态变化、数据表、异常结果和测试。
- 区分三类环境：日常工作区、隔离验收数据库、平台测试夹具。
- 保存当前数据库备份并验证可读性，记录恢复步骤。
- 为真实平台和在线模型使用明确的功能开关，默认不进行外部发送。
- 检查仓库版本管理状态；建立小批次变更和评审记录，不擅自覆盖现有用户修改。
- 建立开源参考清单：仓库URL、commit/tag、许可证、借鉴模块、是否直接复用代码。
- 记录尚未验证能力，避免README、页面文案和实现不一致。

### 交付物

- 功能—接口—测试映射表。
- 架构决策记录与开源参考记录。
- 基线测试结果、备份及恢复说明。

### 验收

所有已显示给用户的功能都有明确的实现状态；没有“仅显示成功提示”的假操作。

## 6. M1：真实性、安全和立即修复项

### 6.1 平台结果不能由调用完成推断

- 将 commandId、Runner任务ID、平台业务ID、平台回执ID分开。
- BOSS发送后检查正确会话中的消息、发送状态和内容摘要。
- 猎聘检查MCP isError及平台业务结果，不只检查HTTP状态。
- 无明确业务确认时使用 UNKNOWN_OUTCOME，不补造平台回执。
- 保留脱敏证据：平台ID、时间、业务状态、响应摘要；截图仅在确有必要且受控时保存。
- 已沟通、已发送消息、已提交简历、已存在投递必须分别展示。

### 6.2 绑定正确的页面与材料

- 预检同时核对平台账号、职位ID、公司、岗位及实际使用的简历。
- 提交前重新核对关键字段；页面内容变化使原确认失效。
- 修改材料、招呼语、答案或岗位快照时重新计算确认摘要。
- 在绑定未完成前，界面明确说明是“使用平台侧简历”还是“发送指定文件”。

### 6.3 Runner鉴权与设备归属

- 新增短时配对流程，用户在本机确认设备归属。
- 每台Runner生成独立设备凭据；避免复用开发默认密钥。
- 所有任务、审批签发、查询、取消、人工恢复接口均校验调用方。
- 命令包含用户/设备/任务/输入摘要/时间/nonce；防重放记录持久化。
- 默认仅监听本机；远程Core优先由Runner主动拉取所属任务。
- CORS与Origin校验作为额外约束，不代替认证。
- 日志、事件流和附件读取同样执行归属校验。

### 6.4 立即修正评分事实来源

- 匹配仅读取当前发布版本的允许字段。
- 排除 sourceDocument、历史原文、解析元数据、内部ID和已隐藏章节。
- 先补否定句、单词边界和复合要求的反例测试。
- 尚未引入语义模型前，将词项重叠明确命名为规则相关性。

### 验收

以下情况必须进入失败、未知或待确认，而不是成功：
平台业务失败、空响应、错误会话、材料改变、未配对设备、重复确认凭据、过期确认、无明确平台回执。

## 7. M2：统一简历模型与导入

### 7.1 动态模型

- Profile + Sections[] + Items[]，每层使用稳定ID。
- 支持多个项目、教育和实习/工作条目。
- 支持技能、奖项、证书、自定义章节。
- 章节和条目可排序、隐藏；空章节不输出。
- 时间采用明确的起止字段，额外保留原始展示文本。
- 简历名称、目标方向、模板、语言成为可编辑属性。
- 编辑器、预览、导出、匹配共用规范化内容，避免多套字段转换漂移。
- 增加schemaVersion和旧数据转换器；迁移保留未知字段，不静默丢弃。

### 7.2 草稿与发布

- 草稿修订号和发布版本号独立。
- 保存冲突提供“重新加载/查看差异/手工合并”。
- 发布必须绑定预期草稿修订号，防止陈旧页面覆盖新草稿。
- AI应用与历史恢复先检查未发布修改。
- 跨标签页提示更新；退出与切换简历前处理未保存内容。
- 服务返回后才显示“已保存”，并展示实际保存时间。

### 7.3 导入工作流

文件选择 → 类型/大小检查 → 文本与版面提取 → 字段候选 → 原文对照 → 用户确认 → 草稿

- PDF/DOCX/TXT字段回填，不再将全文作为个人简介。
- 保留字段来源的页码、文本范围和解析置信度。
- 双栏PDF、表格DOCX、乱码、日期不完整作为独立测试场景。
- 扫描PDF可选OCR；未配置时明确提示，不输出看似正确的空简历。
- JSON Resume通过转换器导入；区分单份简历JSON和工作区备份JSON。
- 不向第三方模型发送联系人等非必要字段。

### 验收

至少包含多个项目、两条教育、实习、技能和自定义章节的测试文件，导入/编辑/发布/再导出后：
- 内容数量和顺序一致。
- 额外章节不丢失。
- 每个待确认字段可定位到原文。
- 旧版简历可转换并保留原始副本。

## 8. M3：文件导出与材料一致性

### 任务

- 将浏览器打印保留为快捷方式，新增稳定的文件生成服务。
- 第一版先保证一种中文单栏模板，随后再增加模板。
- 固定纸张、边距、字体来源和模板版本；禁止静默字体替换。
- 长文本、跨页、空章节、链接和中文字体需要排版测试。
- 每份导出记录绑定 resumeVersionId、templateVersion、renderConfigHash。
- 文件生成成功后计算真实字节的SHA256，记录格式、大小、页数和状态。
- 文件以不可变产物保存；失败导出不标为成功。
- 下载检查账号归属；文件路径不直接暴露为任意本机访问接口。
- 增加导出后文本再提取校验，核对内容、阅读顺序及隐藏章节。

### 材料绑定

建立投递材料记录，区分：
1. LOCAL_FILE：确定的本地生成文件及其真实哈希。
2. PLATFORM_RESUME：明确的平台简历ID与可核对的内容快照。
3. CHAT_ONLY：仅沟通，不声称已发送简历。

平台不支持选择具体材料时，界面展示限制并要求用户确认平台侧材料，而非虚构文件上传能力。

### 验收

同一导出请求可追溯、重复请求幂等；用户预览的文件就是本次提交所绑定的产物。DOCX导出可在PDF稳定后列入增强范围。

## 9. M4：JD证据与统一评分

### 9.1 原子化JD要求

- 将一句中的不同技能拆为独立要求。
- 保留 AND/OR 关系，区分“同时具备”与“任一满足”。
- 学历、年限、地点、语言等使用结构化约束。
- 记录 requirementId、原文quote/offset、来源、置信度和确认状态。
- 人工修改要求生成新的要求集版本，不修改已用于历史报告的快照。
- 公司、职位名称、地点、薪资支持校正并留下历史。
- “未知”不是“无限制”，“未提取到”不是“确定缺失”。

### 9.2 单一评分职责

- Core管理版本、权限与持久化。
- FastAPI提供唯一的评分实现；过渡期可保留Java算法作为显式baseline。
- 不再让两个不同算法都叫同一个规则版本。
- 先完善规则：边界、否定、别名、经验深度和硬条件。
- 再引入可选语义模型，对齐语义与词项重叠的命名。
- 权重由配置与评测共同确定，不预先宣称某个比例最优。
- 必须条件未满足时单独显示，不让加分项掩盖硬冲突。

### 9.3 证据分类

- 明确满足：当前内容存在直接证据。
- 部分满足：只证明技术提及或部分实践。
- 未提供证据：材料中未写明，不推断用户没有能力。
- 明确冲突：结构化条件相互矛盾。
- 待人工判断：解析歧义或证据不足。

### 9.4 可复现报告

记录简历版本、JD版本、要求集版本、词典版本、规则/模型版本、输入哈希与结果哈希。
重新运行历史报告必须使用当时快照；换新规则要生成新报告并明确标记。

### 评测

先建设50组覆盖正常与反例的标注样本，再扩充到100–200组。训练/调参样本与留出验收样本分开。
评测技能识别、否定判断、硬条件、证据定位和岗位排序，不把匹配分数解释为录用概率。
数值指标先测基线再设提升目标；错误平台成功和测试夹具污染属于零容忍回归用例。

## 10. M5：AI建议接入与事实保护

### 任务

- 建立Provider工厂，将已有在线客户端接入实际建议流程。
- 配置只保存在服务端/受控本机；前端不回显密钥。
- 支持离线规则与在线模型两种明确模式，响应标记真实来源。
- 统一JSON序列化和输出Schema；拒绝多余字段及非法patch。
- 模型只接收必要经历片段和岗位要求，不默认发送整个工作区。
- 简历/JD文本视为数据，不作为模型操作指令。
- 生成建议绑定稳定条目ID、原文哈希、基础版本及支持证据。
- 新增技术、数字、工作年限、证书或公司经历必须有来源，否则转为补充信息问题。
- 用户“编辑后采用”单独记录为用户编辑，不继承未经复核的模型置信度。
- 应用前展示差异；有未保存草稿、原文变化或版本变化时先合并或重新生成。
- 避免用全文替换修改多个同文条目。
- 记录模型、耗时、token/成本信息；离线模式与降级也清楚标识。

### 验收

正常响应、超时、限流、非法JSON、提示注入、虚构数字、路径越界、原文变更均有测试。
模型输出未经验证不写入草稿或发布版本。
用户能够查看建议来源、取消选择及恢复历史版本。

## 11. M6：岗位发现与可靠执行

### 11.1 岗位数据模型

采用：
- PlatformJob：平台职位身份。
- JobSnapshot：本次看到的正文与元数据，不可变。
- DiscoveryRun：搜索参数与进度。
- DiscoveryRunJob：批次与快照的关联。
- MatchRun：指定简历与快照的匹配结果。

不通过修改职位的旧批次ID来“去重”。重复发现可复用相同内容快照，内容变化则新建快照。
保存原始来源字段及标准化字段，缺少有效职位ID时标记无效数据，不用数组下标伪造业务ID。
跨平台相似岗位先标记候选重复，避免误合并不同招聘方或不同岗位。

### 11.2 搜索适配

- 多城市、分页、薪资单位、经验、学历分别做平台转换。
- 列表摘要与完整JD分开；最终评分优先使用完整JD。
- 缺页、超时、登录失效、无结果和解析器失效分别展示。
- 持久化发现任务的Runner ID，前端刷新后能继续查看原任务。
- 保存新出现、正文变化、关闭和重新开放等事件。

### 11.3 持久化调度

- API快速创建任务并返回202；不在数据库长事务中等待浏览器。
- 同一事务写任务和Outbox，后台读取后交付Runner。
- Runner以设备身份获取任务；执行租约/心跳防止同一任务并发执行。
- 每次外部命令有稳定commandId、inputHash、attempt及状态版本。
- 网络重试使用原命令身份，不通过生成新ID掩盖未知结果。
- 执行事件单调编号，重复/乱序回报去重。
- 前端采用无重叠轮询或认证事件流，仅展示状态。
- 失败重试分类：读取/预检可有限重试；提交后超时先核对。
- Outbox与幂等只能控制自身系统行为，不宣称外部平台支持“恰好一次”。

### 11.4 建议状态机

任务：
DRAFT → PREPARING → AWAITING_APPROVAL → QUEUED → RUNNING → VERIFYING → SUCCEEDED

分支：
- AWAITING_LOGIN / AWAITING_CAPTCHA / AWAITING_INPUT
- FAILED_PRE_SUBMIT
- UNKNOWN_OUTCOME → RECONCILING → SUCCEEDED / NEEDS_MANUAL_REVIEW
- CANCEL_REQUESTED → CANCELLED（仅在确认尚未产生动作时）
- EXPIRED（需重新预览与批准）

审批：
PENDING / APPROVED / EXPIRED / INVALIDATED / CONSUMED

审批到期在实际不可逆动作前检查；长队列不自动延长用户批准。
若任务已可能提交，取消只停止后续动作，不把历史改成“未发送”。

### 11.5 平台专项适配

BOSS：
- 精确职位、公司和会话识别。
- 完整JD读取及平台过滤转换。
- 区分打开聊天、发送文字、发送附件。
- 登录状态不以“浏览器已启动”代替。
- 消息/附件发送后的业务证据校验。
- 选择器版本与页面契约测试。
- 页面验证由用户完成。

猎聘：
- 根据实际MCP工具列表核对参数Schema和能力。
- Token过期、权限不足、工具不存在独立处理。
- 平台简历读取、材料预览与用户确认。
- 检查业务成功结果；有查询能力时核对历史投递，无查询能力时明确人工核对。
- 搜索分页与jobKind等来源字段完整保留。
- 不声称支持工具列表之外的功能。

### 故障验收

提交前/中/后断网；Core回滚；Runner断电；日志写入失败；数据库短暂不可用；令牌过期；重复命令；重复人工恢复；任务并发启动；页面变化。
所有场景均检查平台动作次数、业务状态和审计记录是否一致。

## 12. M7：跟进、部署与交付

### 12.1 求职跟进

- 区分沟通、消息、附件与简历投递。
- 投递记录绑定公司、岗位快照、匹配、材料与回执。
- 增加下一步、面试时间、备注、联系人及事件时间线。
- 增加拒绝、撤回、岗位关闭、已入职等明确终态。
- 提醒先做站内待办；邮件/系统通知在用户启用后实现。
- 统计说明分母和时间范围，不显示没有依据的提升比例。
- 支持搜索、筛选、分页和导出。

### 12.2 账号与隐私

- 登录限流、会话撤销、密码策略及错误信息统一。
- 找回密码需要邮件服务时作为部署依赖，未配置就不显示可用。
- 服务端密钥、文件访问、Runner配对和日志脱敏专项检查。
- 文件大小、实际类型、压缩文档膨胀限制、OCR资源上限。
- 完整备份与恢复格式；删除语义、引用关系和回收策略明确。
- 已废弃演示账号与日常工作区隔离，测试夹具不进入生产UI。

### 12.3 工程与部署

- PostgreSQL集成测试纳入CI，覆盖事务、并发、TEXT字段、约束与迁移。
- 数据变更采用兼容新增 → 回填 → 校验 → 切换；破坏性清理另行确认。
- 升级前备份，在独立环境实际恢复，不只检查备份文件存在。
- 仅暴露必要入口；AI Worker与Runner不默认公开到互联网。
- 非敏感requestId贯穿Core、AI与Runner。
- 指标包括排队时长、P95耗时、失败分类、未知结果率、重试次数、模型成本。
- 列表分页，减少逐条加载审计造成的N+1请求。
- 增加依赖扫描、格式检查、API契约和端到端测试。
- Docker容器真启动与健康验证独立于compose config。
- 真实平台首次验收只做用户明确确认的一次小范围动作，核对后再扩大使用范围。

## 13. 建议新增/改造的数据实体

以下为概念设计，编码前需核对现有表，优先扩展而非重复造表。

| 实体 | 核心用途 |
|---|---|
| ResumeDraft / ResumeVersion | 草稿并发、内容schema版本、不可变发布快照 |
| ResumeArtifact | 文件、模板、字体/渲染配置、实际SHA256 |
| ImportJob / FieldEvidence | 异步导入、字段原文与人工确认 |
| RequirementSetVersion | 不可变要求集及人工校正历史 |
| ScoringRuleSet | 算法、权重、词典/模型版本和配置哈希 |
| MatchEvidence | 当前简历条目ID与JD原文位置对应 |
| SuggestionBatch / Patch | 基础版本、目标原文哈希、审核与应用状态 |
| PlatformJob / JobSnapshot / DiscoveryRunJob | 职位身份、快照与发现历史 |
| RunnerDevice / DeviceCredential | 用户设备配对、密钥轮换和撤销 |
| AutomationTask / Outbox / TaskLease | 持久化调度、可靠交付和执行租约 |
| Approval / ConsumedNonce | 确定输入的一次确认与防重放 |
| ApplicationMaterial / PlatformReceipt | 实际材料、平台证据和业务结果 |
| ApplicationEvent / FollowUp | 求职时间线与待办提醒 |

敏感文件路径和密钥不直接进入通用API响应。新增索引围绕user_id、created_at、状态及任务领取条件设计。

## 14. 接口与前端约定

- 创建异步任务返回taskId、状态和可查询地址。
- 区分请求被接收与业务完成。
- 用户所有权由服务端校验，不信任前端传入的userId。
- 修改草稿、要求、计划使用预期修订号。
- 创建/提交命令使用幂等键；相同键不同输入返回冲突。
- 错误码区分OFFLINE、AUTH_REQUIRED、SCHEMA_CHANGED、BUSINESS_REJECTED、UNKNOWN_OUTCOME、CONFLICT。
- 响应说明结果来源：规则、在线模型、平台确认或人工确认。
- 前端统一空状态、加载、重试、取消和冲突处理。
- 危险动作按钮清楚写明实际行为，预览与确认步骤不可省略。
- 已完成任务停止无意义轮询；订阅和未完成请求在退出时清理。
